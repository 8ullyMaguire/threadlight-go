# Local Development

Getting Threadlight running on your own machine is a great way to start contributing. Before you begin, you will need a few tools installed on your system. The backend is written in Go, so you will need the Go compiler, version 1.22 or later. The frontend uses Svelte and Vite, so you will need Node.js, version 20 or later, along with npm or another package manager. Threadlight also relies on PostgreSQL for its main database and Redis for caching and session storage, so both of those need to be installed and running before the server will start.

Once you have the prerequisites ready, the first step is to get the source code. Clone the repository from its home on a code hosting platform like GitHub or Forgejo. The command is the usual git clone followed by the repository's address. After the clone finishes, move into the project directory and you will see the same structure described in the architecture overview — the cmd, internal, and web folders are the ones you will spend most of your time in.

Building the backend is straightforward thanks to Go's built-in tools. From the project root, run the go build command with the path to the main server file. This will produce a single binary file that you can run directly. Alternatively, you can use go run during development to compile and start the server in one step. The binary reads its configuration from environment variables, so you will need to set a few before it can connect to the database and Redis. At minimum you need a database URL, a Redis address, and a secret key for signing sessions. A good practice is to create a small shell script or a dotenv file that sets these variables so you do not have to type them every time.

Building the frontend requires a separate step. Move into the web folder and run npm install to download all the JavaScript packages the frontend depends on. Once that finishes, run npm run dev to start the Vite development server, which will watch your files for changes and reload the page automatically. You can also run npm run build to create a production build of the frontend, which Vite will place in a folder that the Go backend can serve.

The database needs to be set up before the server can work. Create a new PostgreSQL database for Threadlight and make sure your database user has permission to create tables and run migrations. When you start the Go server for the first time, it will automatically apply any pending migrations from the migrations folder, creating all the tables the application needs. If you ever need to reset the database, you can drop it and let the migrations re-create everything from scratch.

Running tests is easy and a great habit to build. For the Go backend, run go test ./... from the project root to execute all the tests in every package. The test suite covers the handlers, services, and database operations. For the frontend, you can run npm test in the web folder to check that the user interface components work correctly. Before submitting a pull request, it is always a good idea to run the full test suite and make sure everything passes.

As you work on Threadlight, a few common commands will become second nature. Use go build to compile the backend, go run to build and start it in one step, and go test to run the tests throughout the project. For the frontend, npm run dev starts the development server with hot reloading, and npm run build creates the final production files. If you ever need to check the available command-line flags, run the built server binary with the help flag to see what options are available. And if you get stuck, the project's issue tracker and community chat are good places to ask questions and find help from other contributors.
